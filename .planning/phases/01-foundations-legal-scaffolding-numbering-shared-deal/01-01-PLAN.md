Create `tools/check_repo.py` as a stdlib-only Python 3 script (D-05). Import only from the standard
library — `re`, `sys`, `argparse`, `pathlib` are sufficient; adding any package-manager dependency
is prohibited by PROJECT.md's zero-dependency constraint. Its module docstring must state its own

In this task the script implements the four ID-integrity checks D-05 names, reading its ranges from
`NUMBERING.md` rather than hardcoding them, and emitting one violation line per finding with a
stable code prefix:
- `dup-id` — an ID appears in more than one row of the Allocated IDs table.
- `range-id` — an allocated `PF-<s>.<n>` has `n` above section `s`'s ceiling or below its start, or
  an allocated `MC-<n>` sits outside the dimension block its row claims.
- `revived-id` — an ID appears in both the Allocated IDs table and the Deprecated IDs table.
- `undefined-id` — a token matching `PF-\d+\.\d+` or `MC-\d+` appears in a scanned file and is
  absent from the Allocated IDs table. Scan `skills/`, `examples/`, and `README.md`, skipping
  fenced code blocks and skipping `NUMBERING.md` itself.

Absence is not failure, only contradiction is (CONTEXT.md `<specifics>`): a missing `skills/`
directory, a missing `README.md`, a missing `examples/` directory, and an Allocated IDs table with
zero data rows must all produce exit 0. Violations are sorted ascending by ID before printing so two
runs on identical input produce byte-identical stdout. Exit 0 with a one-line green summary when
there are no violations; exit 1 and print the violation lines when there are.

Implement `--self-test` as a mode that runs each check family against an inline known-bad fixture

bad fixture and stays silent on the good one. Print `FAIL` on the failing line and exit non-zero if
any assertion does not hold; print a pass summary and exit 0 otherwise. The self-test must not read
or write any file outside a temporary directory it creates and removes.

## Trust Boundaries

This phase produces a public documentation repository with no runtime, no network surface, no
authentication, no data store, and no user input. The classic ASVS L1 boundaries (client to API,
service to database, session management, access control, cryptography at rest and in transit) have
**no counterpart in this phase** and are not padded into the register below. The boundaries that
genuinely exist are content and legal-exposure boundaries.

| Boundary | Description |
|----------|-------------|
| Framework source material -> repository content | Proprietary framework wording could cross into a public MIT-licensed repository through paraphrase that is too close, or through a model reproducing training-portal text. |
| Fictional example data -> public repository | Invented company, person, and deal facts could inadvertently match a real entity once published. |
| Canonical registry -> every downstream file | A silently dropped or reworded attribution pointer, or a drifted canonical figure, propagates into every artifact that cites it. |
| Repository -> forks, scrapers, and search indexes | Filenames and headings are indexed and forked in ways body text is not, so a mark in a path has a wider blast radius than the same mark in prose. |
