registry enforce what NUMBERING.md and the checker's own docstring already claim they enforce.

Purpose: 01-VERIFICATION.md and 01-REVIEW.md each left the same class of finding behind the

unrelated canonical value is silently accepted — a real ceiling the docstring does not declare
while it does declare the bare-count one.

Output: a `tools/check_repo.py` where the figure-table exemption is bounded by the table rather
than by the next heading, MC IDs are validated per dimension block (D-02), and every known ceiling
is written into the docstring where a reader can see it.
</objective>

## Deferred with rationale

**WR-02's stronger fix — binding each canonical figure to its key at the point of use — is
deliberately not implemented here.** It would require annotating figure citations inside
`examples/deal-brief.md` prose with their canonical key, which changes the frozen
`## Canonical figures` interface that D-10 instructs the project to treat as an API, and rewrites
content 01-02 shipped and the verifier confirmed. That is a change to a frozen Phase-1 artifact,
not a checker bugfix, and the review itself names disclosure as the minimum. This plan implements
the disclosure and pins the collision behaviour with a fixture so it is documented-and-tested
rather than accidental; the key-binding upgrade belongs with whichever later phase needs stronger
figure provenance (Phase 5's eval scenarios are the likely trigger).

**An import-purity self-check is not added.** The verifier's stdlib-only confirmation was an ad-hoc
AST scan run outside the repository, and 01-PATTERNS.md records that no in-repo precedent exists.
No gap, requirement, or review finding asks for one, and `.github/workflows/ci.yml` already carries
zero `pip install` lines. Adding it would be manufactured work; the AST assertion stays where it
belongs, in this run's task acceptance criteria.
