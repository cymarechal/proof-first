<objective>
Make the regression class that produced this phase's BLOCKER impossible to reintroduce silently, by
running every check against a deliberately broken copy of the repository's real documents on every
push.

Purpose: the defect 01-VERIFICATION.md found was not a missing check. It was a check that existed,
was named as covered by its own self-test, ran in CI, and could not fire. The self-test proved the
logic against a document shape the project's own plans required NOT to exist. Fixing the parser
(01-05) and the two under-enforcing checks (01-06) removes today's instances; only an adversarial
check against production content removes the class. The verifier's strongest evidence was a manual
mutation — copy the repo, delete the pointer line from README.md, observe `0 violations`. This plan
commits that method as a mode of the checker itself and wires it into CI, so a future edit that
makes any check inert turns CI red instead of green.

Output: a `--mutation-test` mode in `tools/check_repo.py` with one named mutation per violation
code applied to throwaway copies of the real repository files, a clean control run, and a CI step
that runs it between the self-test and the live check.
</objective>

Add a third mode that applies one deliberate defect at a time to a throwaway copy of the real repository files and asserts that the matching check fires.

Copy helper. Add `MUTATION_SOURCES`, a tuple of the repository-relative paths the checker reads: `NUMBERING.md`, `NOTICES.md`, `README.md`, `examples`, and `tools`. Add `_copy_repo_subset(repo_root, dest)` that copies exactly those entries into `dest`, creating parent directories as needed, and copies nothing else — never `.git`, never `.planning`. Use `shutil.copytree` and `shutil.copy2` from the standard library; `shutil` is the only import this plan adds and it is stdlib, so the zero-dependency constraint holds. Because `REPO_ROOT` resolves from the running script's own location, invoking the copied `tools/check_repo.py` inside `dest` makes `dest` the repository root for that run, which is the same trick the manual reproductions in 01-VERIFICATION.md used.

Mutation registry. Add `MUTATIONS`, an ordered list of records pairing a violation code with a one-line description and a function that takes the scratch root and edits exactly one file inside it. One record per code in `ALL_CHECK_CODES`:
  - `pointer-missing` — remove the line equal to the canonical pointer from `README.md`.
  - `pointer-duplicated` — append a second copy of that line to `README.md`.
  - `pointer-unparseable` — remove the `## Attribution pointer` heading line from `NOTICES.md`.
  - `dup-id` — insert the same allocated-ID row twice into `NUMBERING.md`'s Allocated IDs table, using an ID inside a declared PF range.
  - `range-id` — insert an allocated-ID row whose PF number sits above its section's declared ceiling.
  - `revived-id` — insert the same ID into both the Allocated IDs table and the Deprecated IDs table.
  - `undefined-id` — append a sentence to `README.md` citing a PF ID that is in no allocated row.
  - `dup-figure-key` — duplicate the first data row of `examples/deal-brief.md`'s Canonical figures table.
  - `figure-order` — move the table's last data row to the top of the table, breaking ascending key order.
  - `unlisted-figure` — append a stray currency token on a prose line after the Canonical figures table, which is the file's last section; this is the mutation that would have caught the end-of-file blind spot 01-06 Task 1 fixes.

Each mutation function inserts rows by locating the table's separator row after its `## ` heading and writing immediately below it, which is the only insertion point that works while those tables have zero data rows. Keep each function to one file and one edit so a failure names one cause.

Harness. Add `mutation_test(repo_root)`. First run a control: copy the subset into a scratch tree, apply no mutation, run the checks, and require zero violations — if the control is dirty, report it and fail, because a mutated tree's red would then not be proven content-caused. Then, for each record in `MUTATIONS`, create a fresh scratch tree, apply that one mutation, run `run_all_checks()` against it, and require at least one violation whose message's first token equals the expected code. Finally, require that every code in `ALL_CHECK_CODES` appears in `MUTATIONS`; a code with no mutation is a reported failure, so adding a code later without adding a mutation cannot pass silently. Return True only when the control was clean, every mutation fired, and every code was covered.

Output format is load-bearing, because the fail-first proof in Task 2 greps it to tell a genuinely red harness apart from a harness that never ran. Print exactly these line shapes to stdout, in this order: one control line beginning `mutation-test CONTROL:` followed by the violation count on the unmutated copy; then, per record, a line beginning `mutation-test OK: <code>` when the expected code fired or `mutation-test FAIL: <code>` when it did not, in each case followed by the record's description; then a final line beginning `mutation-test PASS` with the number of codes proven live, or `mutation-test FAILED` with the number that did not fire. Keep the code as the token immediately after the `OK:` or `FAIL:` marker so a grep can anchor on a specific code.

CLI. Add a `--mutation-test` flag to the existing `argparse` parser and dispatch it in `main()` with the same exit contract the self-test uses: exit 0 on True, exit 1 on False. Leave the default live-run path and its `(code, subject)` sort untouched. Add the new mode to the docstring's Usage block.

Do not write anywhere except inside a `tempfile.TemporaryDirectory`. The harness must leave the working tree byte-identical.
