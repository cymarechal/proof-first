<objective>
Prove the whole Phase 2 pipeline on one thin, real slice: three rules — one from PF-0, one from
PF-2 Integrity, one from PF-3 — authored in a production-quality `skills/proof-first/SKILL.md`,
registered in `NUMBERING.md`, indexed in `references/checklist.md`, backed by
`references/deletion-test.md`, and guarded by a new `catalog-id-drift` violation code that is
proven to fire against mutated production content in CI.

Purpose: creating `SKILL.md` switches on four already-shipped checks against it
(`pointer-missing`, `pointer-duplicated`, `undefined-id`, `range-id`) and one more once its scan
root is widened (`unlisted-figure`). Proving that whole path green on three rules — rather than on
thirty-one — catches an architectural dead end after one commit instead of after five plans of
authored prose. The frozen interfaces this task establishes (the marker bracket grammar, the
register heading, the 31-rule ID allocation map) are what Phase 3's check output, Phase 4's
committed examples, and Phase 5's linter all bind to, so they are gated by a decision checkpoint
before any of them is written down.

Output: a real, installable three-rule skill folder; `NUMBERING.md`'s PF-2 sub-block table and
first three Allocated IDs rows; one new CI-enforced violation code; the mutation-test control copy
widened to include `skills/`.
</objective>
