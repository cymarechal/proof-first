<objective>
Give each of the four artifact families its own conventions and its own written expected order, state
how a document is classified into a family before any rule is applied, say what happens when none
fits, and make the four family sections a build-enforced structure rather than a convention.

Purpose: `SKILL.md`'s Write mode already emits a line naming the artifact family it assumes, but no
file anywhere states what any of the four families actually requires, and no file states how the
classification is made or what to do when the document fits none. This plan supplies all of that in
one reference file, so that `03-04` can wire classification and the structural-ordering pass into
check mode with one short sentence each instead of four families' worth of inline detail the token
budget cannot hold.

Output: `references/artifact-patterns.md` with a classification procedure, a no-family fallback, and
four family sections each carrying its conventions and its expected order; one new CI-enforced
violation code with firing and silent fixtures and a registered mutation.
</objective>

`## Executive summary` (ART-03):
- `**Order:**` the sequence this family expects, on one line: the problem reframe, then the business
  case, then the capability list.
- `**Problem reframe:**` the summary opens by restating the buyer's own situation in the buyer's own
  words before naming any product, vendor or capability — cite the allocated opening rule by number
  rather than restating its body.
- `**Business case:**` the case is stated before any capability list, in the terms the person who
  signs is measured on, and it carries its evidence or a marker in place of it.
- `**Capability list last:**` a capability list that arrives before the case has been made is the
  named failure; the list is the support for the case, never the substitute for it.

`## Demo and discovery material` (ART-04):
- `**Order:**` the sequence this family expects, on one line: discovery notes into a demo script, a
  demo script into proof-of-concept success criteria, and success criteria into follow-up.
- `**Discovery notes:**` what the buyer said is recorded in the buyer's own words and attributed to
  the person who said it, so a later document can cite it as supplied customer source material.
- `**Demo script:**` the script shows the capability the discovery notes actually named, in the
  buyer's own scenario, rather than a standard product tour.
- `**Proof-of-concept success criteria:**` the criteria are agreed and written down before the
  proof-of-concept runs, with the measure and who judges it named, so success is not decided
  afterwards by whoever is in the room.
- `**Follow-up:**` what happens next carries a named owner on the vendor's side and a date, and a
  commitment-shaped statement in it raises the review marker the prose catalog already defines.
