## Task 1 — G-03-2: make the classify-before-rules order an instruction, not an inference

**The observed failure.** One of six live write-mode sessions opened with the customer-source-material
question, listed three rule findings (`PF-2.17`, `PF-2.15`, `PF-1.17`), then asked the user to reply
"proceed" and stopped. It never named an artifact family and never drafted. A retry of the identical
prompt conformed, so this is variance the instruction text currently permits rather than a
deterministic break.

**Why the text permits it.** `## Write mode` paragraph 1 fixes the output as "exactly three parts,
in order" with the family line first. Paragraph 2 says to name what counts as customer source
material and "ask for it once, proceeding either way". Nothing relates the two paragraphs. Nothing
forbids emitting a finding before the family line. "Proceeding either way" is the fifth clause of a
34-word sentence.

**Do this.** Two edits, both in `SKILL.md`:

1. In `## Write mode`, make the non-blocking property of the ask its own sentence. The ask and the
   draft land in the same response; a missing answer is not a reason to stop.
2. Add one sentence stating that no rule ID is cited before the artifact family is named, in either
   mode. Put it where both modes read it — the `## Your task` section is the natural home, since it
   already carries the "cite only rule numbers defined in this file" instruction that MOD-05 rests on.

**Budget.** `SKILL.md` is at 3665 words, 4764 estimated tokens, 236 tokens of margin under the 5000
ceiling. Two sentences fit. Measure after editing with `python3 tools/check_repo.py` and record the
new margin in the summary. If the margin drops below 150, pay for it by trimming restatement — a
sentence whose content is already stated in full elsewhere in the same file — never by touching a
rule, a `**Replace with:**` line, or the catalog count.

**Verify.** Re-run the live write-mode check: five `claude -p` sessions from an isolated directory
with the skill installed at `.claude/skills/proof-first/`, one per fixture family plus the ambiguous
one, prompt "Using proof-first, revise this draft into stronger presales prose: <file>". Every
response must name the artifact family before any rule ID appears. Record the pass count honestly —
if it is not 5 of 5, say so rather than rounding up.

## Task 2 — G-03-5: stop using the source's dimension labels as this repository's own nouns

**The finding.** Two independent readers, run blind to `.planning/` and to each other, both returned
ISSUES FOUND against `SOURCES.md`'s reproduction boundary. Verified directly against the file:

| Line(s) | Text | Dimension |
|---|---|---|
| 22, 23, 38, 41, 43 | "economic buyer" | MC-1, MC-6 |
| 64 | "the buyer's decision process" | MC-16 |
| 76 | "the paper process" | MC-21 |
| 85, 88, 92 | "pain", "pains" | MC-26 |
| 99, 102, 104 | "champion" | MC-31 |

These are the frozen `NUMBERING.md` block labels carried into running prose as this repository's own
unattributed nouns, including inside `**Replace with:**` lines, which are instruction text a live
session repeats back to a user.

**The control that makes this a defect rather than a preference.** "decision criteria" and
"competition" appear zero times in the file. MC-11 says "evaluation criteria"; MC-36 says
"alternatives". Two of eight bodies already demonstrate the substitution; six do not. The
inconsistency is the finding.

**Do this.** For each of MC-1, MC-6, MC-16, MC-21, MC-26 and MC-31, replace the source label in the
body and in the `**Replace with:**` line with the document-facing phrase that block's own heading
already uses. MC-21 is the clearest case and the minimum acceptable fix: "the paper process" is not
ordinary business English outside the MEDDIC family, and MC-21's heading already says "the reviews
the document must clear before a signature is possible".

Keep every heading, every ID, the stated count, and the Halverton Mutual facts exactly as they are.
This is a vocabulary edit inside six bodies, nothing else.

**Honest note to carry into the summary.** "economic buyer" and "champion" predate the listed
sources — Miller Heiman's Strategic Selling (1985) for the former, general usage for the latter — so
they arguably fail `SOURCES.md`'s own "coined by a source" test. Both readers said so themselves.
The reason to fix them anyway is consistency with MC-11 and MC-36, not a settled finding that they
are reproduction. Say that in the summary rather than claiming a boundary violation was proven.
