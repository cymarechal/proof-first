<objective>
Build the committed instrument that makes MOD-04's conformance rate reproducible, and prove it
end-to-end on one live path before anything is measured with it.

Phase 3 has measured MOD-04 three times — 5/6, then 5/5, then 14/16 — with an ad-hoc recipe
recreated from prose each time. `.claude/CLAUDE.md` states the standard this repository holds
itself to: "The repo makes measured claims or no claims. Any headline number must be
reproducible from a committed script, with honest caveats stated." The MOD-04 rate is currently
a headline number with no committed script behind it.

Purpose: turn `03-UAT.md`'s `## Method` prose into a stdlib-only runner plus committed fixtures,
so the next measurement — and every one after it — is one documented command.

results file, and a CI line that keeps the scorer honest.

**This is not the Phase 5 evaluation harness.** Phase 5 (EVAL-01..12) owns the prose-quality
linter, the skill-on/skill-off benchmark, and the blind pairwise judge. This runner measures one
thing only: whether a live write-mode session names the artifact-family line before its first
rule marker. It is deliberately scoped and deliberately named `conformance` so Phase 5's harness
does not collide with it.
</objective>

Define module constants:
- `FAMILY_PATTERNS` — a tuple of case-insensitive regexes covering the four frozen family strings as `tools/check_repo.py`'s `ARTIFACT_FAMILY_SECTIONS` spells them (`RFP and RFI response`, `Solution proposal`, `Executive summary`, `Demo and discovery material`), the four write-mode phrasings `SKILL.md` uses (`RFP answer`, `proposal section`, `executive summary`, `demo or discovery material`), and the no-family value `No family fits`. Implement `score_transcript(text)` returning a `(verdict, evidence)` pair. Verdicts are exactly the four strings `conformant`, `no-family`, `rule-before-family`, `unscoreable`. Logic: strip the text; empty means `unscoreable`. Compute `family_at` as the lowest start offset of any `FAMILY_PATTERNS` match, `marker_at` as the lowest start offset of any `MARKER_PATTERN` match. No family match means `no-family`. A marker match strictly before the family match means `rule-before-family`. Anything else is `conformant`. The `evidence` string carries both offsets and the matched family text so a reader can audit a verdict without re-running anything.

Implement `run_session(skill_src, fixture_path, model, out_path, timeout_s)`. Create a fresh directory with `tempfile.mkdtemp()` — this lands outside the repository tree, which is required: a session started inside this repo would pick up the repo's own `.claude/` and `CLAUDE.md` and stop being a clean measurement. Invoke `subprocess.run` with the argv list `['claude', '-p', prompt, '--model', model, '--disallowedTools', 'Write', 'Edit', 'Bash', 'NotebookEdit']`, `cwd` set to the temp dir, `capture_output=True`, `text=True`, and the timeout. Do NOT pass `--bare`: skill auto-discovery must stay on, because the measurement is whether the skill activates and holds on its own description, never because a system prompt named it. | Boundary | Description |
|----------|-------------|

| local filesystem → temp dir | The runner copies `skills/proof-first/` into a `tempfile.mkdtemp()` directory outside the repository. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering | `run_session()` in `evals/conformance/run_conformance.py` | low | mitigate | Build the argv as a Python list and pass it to `subprocess.run` without `shell=True`, so no fixture stem or model string can be interpreted by a shell.
