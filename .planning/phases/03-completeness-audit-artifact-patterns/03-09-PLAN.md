<objective>
Fix CR-01: `score_transcript()` accepts a family-phrase match found anywhere in a transcript as
proof the artifact-family line was declared, when `SKILL.md`'s write-mode contract places that line
first in the output. Several `FAMILY_PATTERNS` entries are ordinary English phrases ("executive
summary", "solution proposal") that recur naturally in the very documents these fixtures produce, so
a genuine `no-family` violation can be scored `conformant` or `rule-before-family` instead — biasing
the measured MOD-04 rate upward, in exactly the direction that flatters the skill.

sessions; remeasuring with the unanchored scorer would burn a second full live-session budget to
produce a third number that cannot be defended. The instrument gets fixed and proven first.

Output: a scorer whose family search is bounded to the prefix window where the contract actually
places the family line, two committed transcript fixtures that prove the fix discriminates in both
directions, and a standing disclosure in `RESULTS-mod04.md` that every pre-fix figure is an
optimistic ceiling and is not recoverable for re-scoring.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repository → `score_transcript()` | Committed transcript fixtures are read from disk and matched with `re`. Content is authored in-repo and crosses only under git review. |
| `claude -p` stdout → `score_transcript()` | Model-generated text, not controlled by this repository, is matched with `re`. This is the one genuinely untrusted input the scorer handles. It is not evaluated, not executed, and not interpolated into any command. |
| `run_conformance.py` → local filesystem | Writes run blocks into the repo and raw transcripts into a temp or operator-named directory. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-09-01 | Tampering | `score_transcript()` window bound | medium | mitigate | The bound is a module constant with its derivation stated in a comment, and both directions of its effect are pinned by committed fixtures plus inline self-test cases; silently loosening or tightening it fails `--self-test` in CI. |
| T-03-09-02 | Denial of Service | `re` matching over model-generated stdout | low | accept | All patterns are literal alternations with no nesting, backreference, or unbounded repetition — no catastrophic-backtracking construct is reachable. The family search is now additionally bounded to 400 characters. |
| T-03-09-03 | Information Disclosure | raw transcripts on disk | low | accept | Transcripts contain only committed fixture content and model output about it. The default `--transcript-dir` is a temp dir and raw transcripts are never committed — which is also, disclosed in Task 2, why the pre-fix figures cannot be re-scored. |
| T-03-09-04 | Elevation of Privilege | `subprocess.run(argv_list)` in `run_session()` / `_git_blob_sha()` | low | accept | Both call sites pass an argv list with `shell=False` (the default); no operator-supplied string reaches a shell. This plan does not modify either call site. |
| T-03-09-SC | Tampering | npm/pip/cargo installs | high | accept | No package-manager install task exists in this plan. `run_conformance.py` is stdlib-only and stays stdlib-only; no dependency is added, so no package legitimacy checkpoint is engaged. |
