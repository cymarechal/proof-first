<objective>
Fix CR-02: `README.md:45` states that no measured claim is published in this repository and that the
benchmark has not run. Phase 3 made the first half false by committing
`evals/conformance/RESULTS-mod04.md` with two percentage-bearing measurement arms. The layout tree and
the what-exists-today list also omit `evals/conformance/` entirely, so a reader has no route to the
measurement that contradicts the sentence.

statement about the repository's own contents, in a repository whose skill exists to catch exactly
this class of unearned claim in someone else's document. Fixing the prose alone would leave the same
regression free to recur the next time a measurement lands, so the fix is mechanical first: a
violation code that fires when README stops pointing at the committed results, then the prose.

Purpose: the repository's stated evidence constraint must hold for the repository's own artifacts
before it is credible when applied to a customer's.
Output: one new discrimination-proven violation code (bringing the total from 29 to 30) and a README
whose Status section, layout tree, and inventory are true as of this phase's own commits.
</objective>

**Decision: `add-alongside`.**

Rationale: this is a genuine singular-to-plural shift and it has a mechanical consequence. `README.md`
has until now carried exactly one pointer of any kind — the canonical attribution pointer parsed out of
`NOTICES.md`, whose cardinality `pointer-missing` and `pointer-duplicated` enforce as exactly one. This
plan adds a second, categorically different pointer (to the committed measurement) governed by its own
new code. The two pointers coexist and are counted separately; the attribution pointer's exactly-one
invariant is unchanged and is asserted in both tasks' acceptance criteria. Promoting "pointer" to a
plural concept in the checker — one shared registry of README pointers — would be the wrong move, since
the two have different cardinality rules and different sources of truth.
</assumption_delta_decision>
