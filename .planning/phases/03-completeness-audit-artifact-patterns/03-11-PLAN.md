<lever_rationale>
The disposition rule from `03-08` says closure requires a lever other than instruction wording. This
lever is at the boundary and the plan states so openly rather than quietly claiming otherwise: it IS
text in `SKILL.md`, because `SKILL.md` is the only surface a skill has. What makes it different in kind
from `03-05` and `03-07` is what it asks for. Those two levers restated the requirement — say the family
first, and here is a fifth value so you always have something to say. This one asks the model to
perform a verification pass over text it has already produced, compare two positions in that text, and
repair the output before returning it. It is a post-generation check, not a pre-generation instruction.

`03-08`'s SUMMARY names exactly this lever, in these terms: extend the existing self-check gate from
"family line present" to "family line precedes any rule marker, verified by re-scanning the drafted
response". This plan implements that and nothing more ambitious, so the measurement in `03-12` tests one
change rather than a bundle.
</lever_rationale>
