<harness_reality>
These cost `03-08` roughly a day of wall-clock. Plan around them, do not rediscover them.

1. `run_conformance.py` appends its run block only when a WHOLE invocation finishes. One invocation
   covering a full matrix loses everything if interrupted. Run **one invocation per fixture per
   repeat** — `--fixtures <one> --repeats 1` — so every completed session is durable the moment it
   lands.
2. Run every invocation in the FOREGROUND. A foreground call is capped at 600 seconds and individual
   live sessions have taken the full 500 and timed out, so pass `--timeout 480` to leave the wrapper
   room to record the timeout as an exclusion rather than being killed with it.
3. Live `claude -p` sessions burn real quota and a usage limit mid-run is a realistic failure. Commit
   after every invocation, so a partial run is an honestly-scoped result rather than a wasted budget.
4. Pass `--transcript-dir` at a durable path OUTSIDE both the repository and the session scratchpad —
   the scratchpad may not survive a session teardown, and raw transcripts are deliberately never
   committed. The run blocks in `RESULTS-mod04.md` remain the durable record; the transcript dir is for
   after-the-fact audit only.
</harness_reality>
