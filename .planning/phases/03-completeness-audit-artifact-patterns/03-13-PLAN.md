<objective>
Close 03-REVIEW.md's Critical finding: `evals/conformance/run_conformance.py`'s live-mode loop holds
every session's result in memory and writes the whole batch only after the full matrix finishes, so an
ordinary interruption between sessions silently discards every session already scored in that
invocation. Make each session durable the moment it is scored, prove that property offline in the
self-test CI already runs, and correct the one itemization in `RESULTS-mod04.md` that does not add up.

Purpose: this repository's governing constraint is that a measured claim must be reproducible from a
committed script. An instrument that can silently discard already-measured, already-scored sessions is
a data-integrity defect in the evidence chain itself, not an operational inconvenience — and
`RESULTS-mod04.md` already documents this exact failure mode destroying two entire measurement
attempts, answered operationally rather than in code.

Output: a durable instrument, a CI-held proof of that durability, and a results file whose stated
counts match their own enumerations.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `claude -p` stdout to `score_transcript()` | Model-generated text, not controlled by this repository, matched with `re`. The one genuinely untrusted input this instrument handles. It is never evaluated, executed, or interpolated into a command. This plan does not change how it is read, only when the resulting verdict line is written. |
| `run_conformance.py` to a spawned `claude` process | `subprocess.run` on an argument list with `shell=False`, `cwd` set to a fresh temp directory, and the mutating tools disallowed. Unchanged by this plan. |
| `run_matrix()` to the results file on disk | The new write boundary. An append-mode handle held open across the run, written and flushed per session. The file path comes from `--out`, which defaults to the committed results file inside the repository. |
| self-test stub to `run_matrix()` | An injected callable replacing the real session runner. It is only reachable from `self_test()`; live mode never accepts a session runner from input. |
