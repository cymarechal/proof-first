the SUMMARY and confirm the printed number matches.

in `.github/workflows/ci.yml` and nothing else.

add an entry to `KNOWN_OPEN_VIOLATIONS` — which is deliberately empty and whose own comment states

writes is `tools/check_repo.py`. `MOD-04` stays unchecked.

**The new check reads a results file; it does not judge one.** It asserts an enumeration is internally
consistent with the count beside it. It makes no claim about whether the measurement is correct,
current, or well-designed — state that as a declared ceiling in the check's own docstring, the way
every other check in this file declares its ceiling.

**Zero package-manager installs.** No `pip`, `npm`, or `cargo` install task exists in this plan, so
`03-RESEARCH.md`'s Package Legitimacy Audit gate is not engaged.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repository files to `check_repo.py` | Every check reads committed text from the working tree. Nothing is executed, evaluated, or interpolated into a shell command; the tool makes no subprocess call at all. |
| real repository to mutation-test throwaway roots | `_copy_repo_subset()` copies exactly the named top-level paths into a `tempfile.TemporaryDirectory`. This plan adds `evals` to that list, widening what is copied. Mutations are applied only to the copy; the real tree is never written. |
| `check_repo.py` to CI exit code | The tool's exit code is the repository's only gate. A check that silently cannot fire degrades that gate without changing its output, which is why every code must be discrimination-proven. |
