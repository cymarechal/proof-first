<objective>
Answer, with a committed measurement, the one Phase 4 success criterion that has never been
answered: do the output style and the pasted system prompt deliver the same discipline as the
installed skill folder.

`04-UAT.md` test 2 has read `blocked — deferred by design` since the phase began, on the stated
ground that it "waits on Phase 5's benchmark." Phase 5 is complete. It shipped
`evals/benchmark/run_benchmark.py`, a 96-generation live run on 2026-09-18, and the whole pattern
for driving isolated headless `claude -p` sessions and scoring them offline. The blocking premise
expired; the item did not become true on its own. Phase 5 measured skill-on against skill-off. It
never compared the three distribution routes to each other, and `prompts/system-prompt.md` says so
in its own generated preamble: "No benchmark has compared a session driven by this file against a
session with the skill folder installed."

This plan runs that comparison and publishes whatever it finds.

The design is one variable. Three arms — `skill-on`, `style-on`, `prompt-on` — receive byte-identical
prompts from the eight committed benchmark scenarios, the same model, the same effort, the same
tool restrictions. They differ only in how the rule catalog reaches the session: a skill folder in
the session's `.claude/skills/`, an output style in its `.claude/output-styles/` with the project
setting that selects it, or the system prompt appended with `--append-system-prompt-file`. Each
session is scored twice by instruments this repository already owns and already self-tests:
`evals/lint.py`'s `lint()` for mechanical proxy violations, and
`evals/conformance/run_conformance.py`'s `score_transcript()` for whether the artifact-family
convention reached the output.

Two things this plan refuses to do. It will not report an arm it could not prove was switched on —
whether a headless Claude Code session honours a project output style is genuinely unverified right
now, and Task 2 settles it with a six-session probe before a dollar goes to the matrix. And it will
not turn an overlapping range at n=3 into the word "equivalent."

Then make the repository's own documentation true again: the derivative preamble that says no such
comparison exists, the README paragraphs about routes 3 and 4, and the ledger.

Output: `evals/routes/run_routes.py`, `evals/routes/raw/`, `evals/routes/RESULTS-routes.md`, a tenth
CI command, a changed generator preamble with both derivatives regenerated, a 49th violation code or
a written refusal, an updated README and WINDOWS ledger, and `04-15-SUMMARY.md`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repository file → session temp dir | a skill folder, a style file or a settings file is copied into a directory a live model session then reads as its own project configuration |
| model output → committed record | text from an external call is written into a file that becomes a published figure |
| committed record → published figure | `--report-only` turns files on disk into the report a reader trusts |
| operator authorisation → live spend | Task 3's checkpoint is the only gate between an autonomous executor and a real bill |
| measurement result → repository's own claims | the generated derivative preamble and the README assert what this measurement found; a wrong result propagates into shipped artifacts |
