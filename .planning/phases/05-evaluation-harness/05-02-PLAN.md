<objective>
Build the whole free half of the benchmark: the scenario set, the raw-record schema, the offline
aggregator, and the report renderer — all proven against committed fixtures, with not one live
call.

Purpose: the paid half of this phase costs roughly $48 and an hour of wall-clock, and spending is
not undoable. Every defect found after the money is spent is a defect that has to be paid for
twice. So everything that can be proven offline is proven offline first, in its own plan and its
own wave, and a plan-review cycle on this plan re-triggers nothing. That isolation is
`05-RESEARCH.md`'s explicit recommendation (Open Question 1) and this plan adopts it unchanged.

Two design decisions here deserve stating rather than assuming. First, this plan builds the
`RESULTS.md` renderer, including EVAL-09's two-section structure and EVAL-10's five-item caveats
block, even though `05-VALIDATION.md`'s requirement map lists those under plan C. The structure
is a property of the renderer and is provable against fixture records today; only its
*satisfaction by real published content* needs the live run. Building it here means the shape is
settled before any money is spent. Second, and for the same reason inverted: this plan commits no
`evals/benchmark/RESULTS.md` at all. A report file carrying fixture numbers would be
indistinguishable from a real one to any reader who opens it, and this repository's standing
constraint is measured claims or no claims. The fixtures render into a temporary directory inside
the self-test; the real file is `05-03`'s to create.

Output: a fresh fictional deal, eight scenarios, a runner whose offline path is proven never to
shell out, and one new line in CI.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI argument → filesystem path | `--out`, `--raw-dir`, `--skill-src`, `--scenarios` reach `pathlib` and `shutil` |
| external model response → committed record | `claude -p` stdout is parsed and written into a file that later becomes a published number |
| committed raw record → published figure | `--report-only` turns files on disk into the report a reader trusts |
| repository skill folder → isolated temp dir | `shutil.copytree` crosses into a directory the model then reads |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-06 | Tampering | argument/path injection via `--out`, `--raw-dir`, `--skill-src` | high | mitigate | every path is constructed with `pathlib.Path`, never string-concatenated into a command; every `subprocess.run` takes a list argv and never `shell=True`; asserted by a self-test scan of the module's own AST (Task 1, ASVS V5) |
| T-05-07 | Tampering | a raw filename built from a free-text value reaching a path traversal | high | mitigate | the `scenario_id` segment is drawn only from the committed `scenarios.json`, and `model`/`condition`/`repeat` come from frozen tuples and an int — no CLI free-text value reaches a filename (Task 1, ASVS V12) |
| T-05-08 | Tampering | a malformed or error-carrying model response silently accepted as generation data | high | mitigate | non-zero exit and `is_error: true` both raise `SessionFailedError` and are recorded `verdict: "unscoreable"` with the real reason; empty or whitespace-only text is treated the same way. This is the bug class that invalidated a whole Phase 3 run (Task 1) |
| T-05-09 | Repudiation | a published figure with no committed record behind it | high | mitigate | `RESULTS.md` is only ever written by `--report-only` reading `raw/`; an unparseable or empty raw file exits non-zero rather than being skipped, so a figure can never be computed from less data than it claims (Task 3) |
| T-05-10 | Information Disclosure | a secret reaching a committed raw record | medium | mitigate | records carry only the fields named in the frozen schema; no environment variable is read into a record, and `--bare`/`ANTHROPIC_API_KEY` is not used anywhere in this phase (Task 1) |
| T-05-11 | Denial of Service | an unbounded live call exhausting budget or hanging | medium | mitigate | `--max-budget-usd 2` per session and an explicit `--timeout` on every `subprocess.run`; the paid matrix itself is gated behind `05-03`'s decision checkpoint (Task 1) |
| T-05-12 | Elevation of Privilege | a generation session writing to the repository | medium | mitigate | every session runs with `cwd` set to a fresh `tempfile.mkdtemp()` and `--disallowedTools` denying the write tools; the repository is never the working directory of a model call (Task 1) |
