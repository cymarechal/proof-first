<objective>
Implement the blind pairwise judge, then spend the money once, under an operator's explicit
authorisation, and publish only what the committed files recompute to.

Purpose: this is the plan that turns three instruments into one measured claim. It is also the
only plan in this phase that is not free and not undoable. `05-RESEARCH.md` Decision 4 measured
the cost from three real invocations during research rather than estimating it: 96 generations
plus 96 judge calls, roughly $48, roughly 58 minutes of serial wall-clock. That arithmetic is an
order-of-magnitude figure derived from n=1-3 samples, not a vendor quote, and the plan says so
rather than presenting it as precise.

Three consequences shape this plan's structure. The judge is built and self-tested offline in
Task 1, so no defect in it is discovered after the money is spent. Task 2 is a blocking decision
checkpoint: an operator authorises the spend, or reduces the matrix, or defers — an autonomous
executor must not walk through that door unattended. Task 3 runs the matrix once, commits every
raw record, and renders the report from those records and nothing else.

The reversibility rating on Task 3 is `costly`, not `one-way`, and the distinction is worth being
precise about because it is easy to get backwards. The *spend* is irreversible — dollars are not
refundable and an hour of wall-clock is not recoverable. But the *decision* this plan implements
is not a one-way door in the architectural sense the taxonomy is about: it publishes no external
contract, writes no format another system reads, and locks in no vendor. If the matrix turns out
to have been run wrong, the remedy is to run it again and pay again — expensive, coordinated,
and entirely possible. `costly` is the honest rating. The checkpoint is inserted anyway, because
`costly` earns a flag by the taxonomy and this particular cost lands on a human's bill.

Output: a judge, one live matrix, 192 committed raw records, and a report whose every number
survives being recomputed from them.
</objective>

**Judge design, frozen by `05-RESEARCH.md` Decision 5:**

- Judge model `claude-opus-5`, judge effort `high`, both recorded per judgement record.
- Three dimensions, each scored 0-10 independently: `evidence` (does every claim carry evidence or
  an explicit gap marker; are there fabricated numbers, reference customers or benchmarks — maps to
  PF-2.x), `clarity` (sentence length, active voice, one claim per sentence — maps to PF-4.x), and
  `persuasive_force` (would a technical evaluator finish this believing the author understands
  their specific problem; does it read as a case for a decision rather than a checklist).
- Texts presented anonymously as A and B. The judge prompt names neither condition, this project,
  nor either rule namespace.
- Both orders run per pair; each dimension averaged across the two orders before comparison.
- A reply that fails to parse or validate, or a refusal, is `verdict: "unscoreable"` with a
  `reason`, excluded from the mean — never defaulted to 0 or to a midpoint. This reuses
  `run_conformance.py`'s `unscoreable` vocabulary discipline (its `VERDICTS` tuple, line 99).
- A genuine tie is recorded as a tie in the win/tie/loss table, not forced to a winner.

**Judgement record schema** is fully specified in `05-RESEARCH.md` Decision 7 with worked example
JSON. Copy it field for field.

**The improvement over the reference implementation** is `--json-schema`. SimpleEnglish's
`run_bench.py` scrapes the judge's free-text reply with a fenced-code-block stripper and carries a
disclosed parse-failure mode. This CLI accepts an inline JSON Schema, confirmed above, so the
reply shape is constrained at the source. If a live probe shows the flag behaving differently from
the help text, record what was observed and fall back to a parse with an explicitly disclosed
ceiling — do not silently adopt the weaker path.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| generated text → judge prompt | model output from one call becomes the input of another |
| judge reply → committed record | an external response is parsed and written into a file that becomes a published number |
| committed raw record → published figure | `--report-only` turns files on disk into the report a reader trusts |
| operator authorisation → live spend | the checkpoint is the only gate between an autonomous executor and a real bill |
