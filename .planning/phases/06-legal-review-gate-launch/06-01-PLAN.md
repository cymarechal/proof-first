<objective>
Confirm one source row against a live public source, record its provenance, and make an unsourced
row a build failure — the whole LEG-04 vertical, proven on one row before it is applied to six.

Purpose: `SOURCES.md` has said since 2026-09-10 that every framework-derived concept must trace to
a listed source, and that a concept with no listed source does not ship. Six of its rows read
`unverified | to confirm at LEG-04`. Grep for `SOURCES` in `tools/check_repo.py` returns only prose
inside other checks' messages, and `SOURCES.md` is absent from `MUTATION_SOURCES`. **The
approved-source rule is entirely unenforced.** A row could be flipped to `verified` with an empty
`Where` cell today and nothing in ten CI commands would notice.

This plan closes that on one row. It is the tracer because it is the thinnest slice that crosses
every layer LEG-04 touches: a real row, a live lookup, a committed provenance record, a new check
code, a mutation entry proving the code discriminates against the real file, and a green CI. The
remaining five rows and the three rights-holder statements are 06-02's expansion over a mechanism
this plan has already proven.

The row chosen is the Andy Whyte MEDDICC book in the Qualification checklist sources table. It is
the highest-value single row: it belongs to the mark family the roadmap criterion names, and a book
is confirmable to a stable public record in a way a vendor marketing page is not.

Output: one confirmed row, one discriminating check code, and a repository where the seventh source
row someone adds cannot claim provenance it does not have.
</objective>

**Two ceilings this check has, both of which go in the docstring** — the file's own precedent is
that a check declares what it cannot do in the same place it declares what it does:

1. It does not fetch the URL. A recorded URL that has rotted, moved, or never resolved reads
   identical to a live one. CI is offline and stays offline; a build that fails because a third
   party had an outage is not a build failure worth having.
2. It does not judge whether the source says what the row claims. That is the same semantic
   judgement `SOURCES.md`'s own "What counts as reproduction" section says no tool in this stack
   performs, and this check does not become the exception.

**The mutation harness precedent to copy.** 03-14 added `'evals'` to `MUTATION_SOURCES` so that
`results-breakdown-count-mismatch` could reach a real file and become discrimination-proven instead
of merely registered, and left a comment saying exactly why. This plan adds `'SOURCES.md'` for the
same reason and writes the same kind of comment. `_copy_repo_subset()`'s docstring names what it
copies and why; extend that docstring rather than silently growing the tuple.

**Why the check is silent on `unverified` rows.** An `unverified` row is an honest statement that
the source has not been confirmed. Firing on it would make the pre-review state a build failure and
would force this plan to confirm all six rows at once — collapsing the tracer. The completeness
half (no row may remain `unverified` once the review record declares the gate passed) is a separate
code, `source-gate-incomplete`, and it belongs to 06-02 because it needs the review record to exist.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| external web page → committed provenance record | content controlled by a third party becomes a line in a file this repository publishes as its legal diligence |
| committed `SOURCES.md` row → build verdict | a Markdown cell becomes a pass/fail signal in CI |
