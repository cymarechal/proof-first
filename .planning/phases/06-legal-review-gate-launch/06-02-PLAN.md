shipped content: it states the posture a reader is entitled to rely on, and `check_pointer` ties it

log into a normative notice file makes the notice harder to read and makes the log's growth look
like posture drift. Separate files, one pointer between them.

plan must not claim coverage that does not exist. It asserts each of the three `###` headings is
present and that each section contains the literal `Non-affiliation`, the case-insensitive phrase

**not** check `Last reviewed`, and does not parse any date. `framework-statement-stale-review` closes
the date half only; the `Paraphrase boundary` label stays unchecked and that is stated as a ceiling.

**Declared ceilings for both new codes**, to go in the module docstring beside 06-01's:

- Neither fetches anything. A recorded URL that has rotted reads identical to a live one.
- Neither judges whether a statement is *true* — only whether it carries a date, and whether that
  date is consistent with the review that claims to have produced it.
- `source-gate-incomplete` reads a declared pass as one frozen literal line. A review record that
  describes a pass in prose without that line is not detected, which is why the marker is a frozen
  string rather than a fuzzy phrase match — a fuzzy match over prose is exactly the fuzzy-proxy
  gate `WINDOWS.md` id 17 records this repository refusing.

**The frozen gate marker.** One line in `LEGAL-REVIEW.md`, matched byte for byte after stripping
leading and trailing whitespace, with no case folding — the same equality discipline `NOTICES.md`
uses for its attribution pointer:

```
Gate status: PASSED
```

Its only other permitted values are `Gate status: OPEN` and `Gate status: FAILED`. The check reads
`PASSED` and ignores the other two.

**The review date marker.** One line in `LEGAL-REVIEW.md` of the form `Review date: YYYY-MM-DD`,
parsed with `datetime.date.fromisoformat`. `framework-statement-stale-review` compares each
`NOTICES.md` statement's `Last reviewed:` date against it.
