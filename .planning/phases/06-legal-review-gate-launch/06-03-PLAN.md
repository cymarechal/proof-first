<objective>
Publish what the benchmark actually supports, and make an unsourced claim a build failure.

Purpose: `README.md` has said since Phase 5 that "deciding what this README states on the strength
of it is Phase 6's work." This is that work, and the honest answer is uncomfortable.

Summed this planning session from `RESULTS.md`'s own committed per-cell tables — arithmetic over
files already in the repository, no new measurement, no new spend:

| Judged dimension | skill-on wins | ties | skill-on losses |
|---|---|---|---|
| evidence | 45 | 1 | 2 |
| clarity | 32 | 3 | 13 |
| persuasive_force | 7 | 3 | **38** |

Across 48 both-orders-averaged pairs each, and consistent across both models rather than driven by
one. The mechanical proxy count, separately, does not move in one direction at all: lower in 8 of
16 cells, higher in 7, equal in 1, with `claude-opus-5` improving and `claude-sonnet-5` worsening.

So this repository's own instrument says the skill makes documents markedly more evidence-dense and
somewhat clearer, and that the same judge finds the un-skilled draft more persuasive four times out
of five. The project's core value is that a technical evaluator finishes the document believing the
author understands their problem. One language model, scoring blind, disagrees.

There is exactly one response consistent with the standard this repository holds its users to, and
with its own precedent of publishing a 10-point decline and a null result rather than burying them:
state all three dimensions with equal prominence, with the model strings and the date, and let the
reader weigh it.

Three mechanisms make that stick. The renderer emits the pooled totals so README cites a committed
figure rather than a hand-sum. A delimited claim region makes "every number here traces to a
committed record" a checkable property instead of a promise. A badge allow-list means no shields
image can ever carry a number this repository has not measured.

Output: a README a technical evaluator can audit line by line, and four check codes that keep it
that way.
</objective>

**Claim-region design.** Two literal HTML comment lines, one of each:

```
<!-- claim-region:start -->
<!-- claim-region:end -->
```

The region is bounded because README legitimately carries numbers that are not measured claims —
`31-rule prose catalog`, `28 worked pairs`, `850-VM`, `40 Oracle Database instances`, `30%`,
`6-hour window` in the before/after example, `Route 4`, and the four install-route numbers. A
whole-file check would either have to whitelist all of those (unmaintainable) or be switched off
(useless). A bounded region is strict where strictness is meaningful.

**Numeric token definition, frozen so the check is not arguable:** a maximal run matching
`\d[\d,.%]*` after stripping a trailing `.` that ends a sentence. `2026-09-18`, `38`, `7.47`,
`30.0%` and `48` are tokens. A token consisting only of punctuation after stripping is discarded.

**Model-string and date anchoring.** A claim-region paragraph containing at least one numeric token
must also contain one of the exact strings `claude-opus-5` or `claude-sonnet-5`, and an ISO-8601
date matching `\d{4}-\d{2}-\d{2}`. Paragraphs are separated by blank lines. The model string
requirement is why LEG-05 says "model versions": a number with no model behind it is a number about
nothing.

**Badge allow-list, frozen in `tools/check_repo.py` with the policy stated beside it:**

| Allowed | Why it is not a claim |
|---|---|
| the repository's own GitHub Actions workflow badge (`…/actions/workflows/ci.yml/badge.svg`) | reports that ten offline scripts exited zero, nothing about document quality |
| a static MIT license badge | states a license, which `LICENSE` already states |

Everything else — any `shields.io` endpoint, any dynamic badge, any badge carrying a number — is a
violation. README carries **no** badges today, so this code ships silent and stays a gate against a
future addition rather than a cleanup of an existing one.

**Badge shape detection:** a Markdown image `![alt](url)` whose `url` contains `badge`, `shields.io`
or ends in `.svg`. Narrow, stated as a ceiling: a badge embedded as raw HTML `<img>` is invisible to
this check, and that is written in the docstring rather than papered over with a second regex.

**The layout-tree gap.** `evals/routes/` exists on disk, is referenced twice in README prose, and is
absent from README's `## Repository layout` tree. `readme-layout-legend-drift`'s own docstring says
it "says nothing about … whether the tree matches the filesystem," so nothing caught this.
`readme-layout-tree-stale` closes exactly that class at one level of nesting: every immediate
subdirectory of `evals/` on disk must appear in the tree. Scoped to `evals/` because that is where
this repository adds families, and scoped to one level because a full tree diff would fire on
`__pycache__` and on every future fixture directory.

**Directories under `evals/` on disk this session:** `benchmark/`, `conformance/`, `routes/`,

present on disk and is not tracked.
