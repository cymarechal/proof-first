<objective>
Decide whether this repository goes public, and if it does, make every unverified launch claim
either verified or honestly still open.

Purpose: five things in this project have been waiting on a human and on a published URL, and no
amount of further engineering moves any of them.

- `WINDOWS.md` id 11: the publish location is the placeholder `<owner>/<repo>`. There is no git
  remote. `publish-location-drift` proves the four occurrences agree with each other and can never
  prove they resolve.
- DIST-01 and DIST-02: neither install route has ever run end to end, because there is nothing to
  install from.
- DIST-03 and `WINDOWS.md` id 16: `04-15` measured that the output style's content reaches a live
  session and activated in 11 of 12 matrix sessions. What stays unobserved is the word
  *permanently* — a human seeing the copied file in `/config` and selecting it. Headless sessions
  have no picker.
- `WINDOWS.md` ids 12 and 17: README's prose quality and its freedom from self-contradiction. Id 17
  records three consecutive rounds where `check_repo.py` reported zero violations and a cold human
  read found a false sentence on the first pass, and records the deliberate decision not to build a
  fuzzy-proxy gate for that class. The method that caught all three was a cold read.

This plan is the gate. Its first task is a blocking decision because publication is the one action
in this project that cannot be undone: a deleted repository stays indexed, stays cloned, stays
archived, and this one names three trademark rights-holders and states a position about live
litigation. Its last task sweeps the ledger, because `/gsd-ship` blocks while `open_count > 0` and
because an entry left undecided at launch is a defect this project shipped without saying so.

The honest possibility this plan is built to accommodate: the operator may choose not to publish
now. In that case every substitution is skipped, id 11 stays open with an updated reason, DIST-01
and DIST-02 stay unverified, and the phase closes having stated exactly that. Deferring is a
decision the plan supports, not a failure it routes around.

Output: either a published repository whose install routes have been observed working, or a
documented decision not to publish — and in both cases a ledger with no undecided entries.
</objective>
