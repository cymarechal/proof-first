# 06-05 — Gap closure for Phase 6 UAT

## Why this plan exists

`/gsd-verify-work 06` ran the six human-judgement checkpoints that 06-04 could not perform, using
five independent readers and a driven interactive session. Three passed. Three returned issues, all
verified against committed files before being recorded.

The three gaps share a shape worth naming before the tasks: **each is a place where a statement
about the work outruns the work**. README claims an evidence discipline its own checker says it does
not enforce; LEGAL-REVIEW.md closes a boundary question on a premise its own registry contradicts;
and a diligence record written by a non-lawyer renders verdicts in the register of an opinion. For
a project whose core value is that a reader finishes believing the author understands the problem,
these are the failure mode the project exists to prevent, found in the project's own front matter.

Task order is deliberate: the README corrections are the smallest and the most exposed (README is
what a reader meets first), the id-6 reasoning is the hardest, and the register pass touches the
most lines.

## Task 1 — Bound README's evidence-discipline claim to what is enforced

**Gap:** G-06-6, finding 1. **File:** `README.md`:229-235.

The sentence currently reads that *every* number in README is sourced from a committed results
file, states model versions and a date, and is checked by `tools/check_repo.py`. All three
conjuncts are false outside the claim region, and `tools/check_repo.py`:405-415 already says so:
"The region is bounded because README legitimately carries numbers that are not measured claims."

Rewrite so the scope of the sentence matches the scope of the two codes it cites. The honest form
distinguishes the two kinds of number README carries — measured claims, which are enforced, and
inventory counts like the 31 rules and 28 worked pairs, which are not and do not need to be.

Do not fix this by adding model strings and dates to the inventory counts. They are counts of
repository contents, not measurements; anchoring them to a model and a date would be the same
overreach in the other direction.

**Verify:** the rewritten sentence, read alone, is true of README as it stands. `python3
tools/check_repo.py` stays green.

## Task 2 — Correct the route count

**Gap:** G-06-6, finding 2. **File:** `README.md`:139-140.

The bullet says `run_routes.py` "measures whether the four install routes deliver equivalent
behaviour". The script's docstring line 2 says "three distribution routes"; `ROUTES = ('skill-on',
'style-on', 'prompt-on')`; `evals/routes/RESULTS-routes.md`:3 says "3 route(s)"; and README's own
:104 says "the three routes".

Either state three, or state four and say in the same breath that routes 1 and 2 both deliver the
installed skill and so collapse into one measured arm. The second is more informative and is what a
reader choosing between routes actually needs; it is also what `RESULTS-routes.md`'s caveat at :47
already implies for route 4.

**Verify:** no sentence in README states a route count that disagrees with `run_routes.py`'s
`ROUTES` tuple without explaining the collapse in the same sentence.

## Task 3 — Carry the current trigger measurement

**Gap:** G-06-6, finding 3. **File:** `README.md`:131-133.

The bullet reports "the recorded run: 9 of 9 must-fire ... and 2 of 5 near-miss" as what
`evals/trigger/RESULTS-trigger.md` holds. That file holds three runs. `WINDOWS.md` entry 24 records
that the n=1 observation "was superseded by the CAT-10 gap-closure round's paired n=5 measurement",
and `RESULTS-trigger.md`:166 records the shipped 439-character description "still measures
`OF_B/SN_B = 9/25` over-fires at n=5".

Arm B is the shipped configuration. A current measurement of what ships exists and README does not
carry it. Replace the n=1 figures with Arm B's, or state plainly that the n=1 run was superseded and
point at the paired measurement. Arm A stays excluded — it was reverted, and 06-04 was right about
that part.

**Watch for the trap this gap came from.** The 06-04 self-read reached this exact spot and
dismissed it as Arm A. The distinction that matters: Arm A is a treatment that does not ship, Arm B
is the control that does. Any correction that only re-justifies excluding Arm A has missed the gap.

**Verify:** every trigger figure in README appears in `RESULTS-trigger.md` in a block that measures
the description currently shipped in `skills/proof-first/SKILL.md`.

## Task 5 — Restate the id-6 reproduction reasoning

**Gap:** G-06-2. **Files:** `LEGAL-REVIEW.md`:161-198, `NUMBERING.md`.

The disposition's load-bearing premise is false against this repository's own registry:

- The eight blocks are Metric, Economic Buyer, Decision Criteria, Decision Process, Paper Process,
  **Pain**, Champion, Competition. Their initials spell **MEDDPPCC**. The repo ships "Pain", not
  "Identify Pain", so position 6 gives P, not I. "It *is* the acronym, letter by letter" is false.
- "Reordering ... would produce a different word" is false for Decision Criteria ↔ Decision Process
  (both D) and Champion ↔ Competition (both C). Four of eight positions are letter-ambiguous.

The conclusion is probably still right, on grounds the document does not state: eight two-word
labels are short phrases, and where expression merges with a mnemonic, protection is thin. Restate
on those grounds, or reopen the entry. Do not patch the premise — a diligence record whose declared
value is that the reasoning is written down cannot carry a reasoning step that a reader can falsify
from the file next to it.

Two further items in the same pass:

- **Test the fourth prong.** `SOURCES.md` defines four reproduction triggers; id 6 argues one.
  The fourth — "a term coined by a source and adopted here as this repository's own label" — is
  never reached, though the disposition's own step 3 says "The eight names are **labels** for the
  blocks". id 3 runs its prongs explicitly; id 6 should too.
- **Reconcile `NUMBERING.md`:9.** It names the namespace "the MEDDICC completeness audit" — a
  seven-element expansion — over an eight-element table whose extra element is Paper Process.

**Verify:** no sentence in the restated disposition is falsifiable from `NUMBERING.md`. Every one of
`SOURCES.md`'s four prongs is either applied or explicitly stated not to apply.

The opening disclaimer is good and should be kept verbatim. The problem is that it governs the
reasoning layer and not the verdict layer, and the verdict layer is what a skimming reader consumes
and what gets quoted. Changes, smallest set that closes most of the gap:

1. `Gate status: PASSED` at **line 5**, above the disclaimer at line 7. Move it below the
   disclaimer or rename it to something that does not read as clearance. While there, reconcile it

2. The two `Disposition:` headings (:138, :164). Reword to describe what was done rather than what
   was concluded. "Disposition" is a term of art for how an adjudicator resolves a matter, and

3. :155 "by none exclusively" — an unbounded negative assertion about third parties' rights that
   the described diligence cannot establish, and broader than the walk-back at :158. Cut or bound it.
4. :187 "not a source identifier the repository could be seen to be **trading on**" — a court
   holding applied to the author's own exposure, in trademark's own framing. Bound it to what was
   read.
5. :240-241 "which is the disclaimer that makes a coincidental name a coincidence rather than a
   depiction" — asserts a mitigation is legally sufficient. Replace with what the files state.
6. The ledger. :420-421 defines `Fixed` as "the defect is gone from shipped content"; ids 3 and 6
   are booked Fixed and no shipped content changed. Add a state for judgement-based closures, or
   move them to `Waived`. The 11/9/8 counts at :455 follow.

**Verify:** read the file's headings, ledger column and bolded verdicts alone, skipping all prose.
